This project is designed to generate `dump.cs` from a locally installed *SCP: Secret Laboratory* client.
The Dumper invokes the IL2CPP runtime APIs exported by `GameAssembly.dll` via Frida to enumerate assemblies, types, and member information, producing a C#-style dump file.

A dynamic runtime approach is used because the current game client's metadata usage region contains sentinel values or obfuscated/interfering data, which causes traditional static registry search tools to fail at reliably locating `CodeRegistration` and `MetadataRegistration`. By calling runtime exported APIs directly, this tool does not rely on static signature scanning or offset calculation.

## Requirements

- Windows PowerShell 5.1 or PowerShell 7
- Python 3
- Python `frida` package

Install Frida tools:

```powershell
python -m pip install frida-tools
```

## Quick Start

```powershell
cd <project-directory>
powershell -NoProfile -ExecutionPolicy Bypass -File .\src\launcher\dump.ps1
```

Default settings:

- Game Path: `C:\SteamLibrary\steamapps\common\SCP Secret Laboratory`
- Output File: `<project-directory>\output\dump.cs`
- Initialization Wait Time: 20 seconds
- Mode: Frida spawn mode

The Dumper spawns a temporary client process, completes enumeration, and terminates only the temporary process it created, leaving any other running game clients untouched. If an existing `dump.cs` is present, it will be automatically backed up as `dump.YYYYMMDD-HHMMSS.cs` upon successful generation of the new dump.

## Parameter Options

```powershell
# Specify custom game path and output path (relative output paths are based on project root).
.\src\launcher\dump.ps1 -GamePath 'D:\Games\SCP Secret Laboratory' -OutputPath 'artifacts\dump.cs'

# Increase IL2CPP initialization wait time (warmup seconds).
.\src\launcher\dump.ps1 -WarmupSeconds 30

# Attach to a specific process by PID.
.\src\launcher\dump.ps1 -ProcessId 1234

# Attach to the latest running SCPSL.exe process.
.\src\launcher\dump.ps1 -Attach
```

*Note: Some client versions may reject late process attachment; using the default spawn mode is recommended.*

## Output Content

The generated `output\dump.cs` includes:
- Assemblies and namespaces
- Classes, structs, interfaces, and enums (along with constant values)
- Inheritance relationships and field offsets
- Properties, method signatures, parameters, and tokens
- Method RVAs and VAs located inside `GameAssembly.dll`

When the game updates, simply re-run the Dumper to produce a new `dump.cs` matching the latest game version.

## How It Works

Collaboration workflow among the three modules (see detailed flowchart in [docs/flowchart.md](docs/flowchart.md)):

1. `dump.ps1` verifies game files, Python, and Frida dependencies, sets up CLI parameters, and launches the driver.
2. `runtime_dumper.py` spawns a temporary client process via Frida (or attaches to an existing one), waits for IL2CPP initialization, injects the enumeration script, receives chunked data, and writes atomically to a temporary file.
3. `runtime_dumper.js` calls exported runtime APIs such as `il2cpp_domain_get_assemblies` to iterate over all types and members, constructs C#-styled pseudocode, and streams back text in chunks via Frida IPC messages.
4. The driver validates the output, backs up any existing dump file, atomically replaces `output\dump.cs`, and terminates only the temporary process it spawned.

## Notes

- The Dumper does NOT modify `GameAssembly.dll` or `global-metadata.dat`.
- The default workflow does not connect to game servers or any remote services.
- Do NOT close the temporary client process manually during dumping.
- Generated directories such as `output\` and `vendor\` are ignored by `.gitignore`.
